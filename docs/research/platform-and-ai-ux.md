# Platform and AI UX: what Apple and Google recommend, and what this app can use

Sources read 2026-11-08. Package facts are for Expo SDK 58 and `@react-native-ai/apple`. Anything not stated by a source is marked [INFERENCE].

## 1. AI UX guidance, checked against the app

| Guidance | Source | Where the app stands |
|---|---|---|
| Keep people in control. Show **Edit, Undo, Retry** near generated content. Ask before significant actions on someone's behalf. | [HIG Generative AI](https://developer.apple.com/design/human-interface-guidelines/generative-ai) | ✅ The user confirms every draft. Auto-apply needs a high-confidence, grounded match and can be undone (`inbox/thunks.ts`). |
| Change the presentation by confidence: when it's lower, ask the person to confirm. Express confidence in plain words. | [HIG ML › Confidence](https://developer.apple.com/design/human-interface-guidelines/machine-learning#Confidence) | ✅ Shows an "Unsure match" badge, and the user picks the application (`TriageResultPanel.tsx`). |
| **Attribution**: give the basis for a result, factual and not too specific ("Because you've read mysteries"). | [HIG ML › Attribution](https://developer.apple.com/design/human-interface-guidelines/machine-learning#Attribution) | ⚠️ A triage result shows the category, but not *why* it matched. Grounding already checks that the email names the company (`triage.ts`), so the reason exists in code. |
| Prefer **guided corrections** (suggest alternatives) over freeform ones. Persist corrections. | [HIG ML › Corrections](https://developer.apple.com/design/human-interface-guidelines/machine-learning#Corrections) | ⚠️ Undo reverts a wrong match. It doesn't offer "Wrong application? Pick another". |
| Give specific progress messages ("Summarizing key themes…", not "Processing…"). | [HIG Generative AI › Outputs](https://developer.apple.com/design/human-interface-guidelines/generative-ai) | Not audited. |

| **Increase automation gradually, under user guidance**. Don't act on assumptions. Explain which data was used. | Google PAIR: [Explainability + Trust](https://pair.withgoogle.com/chapter/explainability-trust/), [Errors](https://pair.withgoogle.com/chapter/errors-failing/) | Auto-apply is always on. An "Ask me first / Apply automatically" setting would follow PAIR. |
| Automate tasks that are tedious and have an agreed "correct" answer. Augment tasks where people disagree on what's correct. | [PAIR User Needs](https://pair.withgoogle.com/chapter/user-needs/) | Triage fits *automate*. Answer feedback fits *augment*, so keep "stronger answer" framed as a suggestion. |

**Policy guardrail.** Apple's [acceptable use requirements](https://developer.apple.com/apple-intelligence/acceptable-use-requirements-for-the-foundation-models-framework) prohibit decisions "without human supervision that have a material impact on individual rights, in high-risk domains, including in employment." The app only changes the user's own records, but keeping confirm and Undo is the safe reading [INFERENCE].

## 2. Foundation Models: limits and best practices

- **Context size varies by device. Read it at runtime once the library allows it.** On iOS 27, AFM Core has a 4–8K context, AFM Core Advanced 8K, and Private Cloud Compute (PCC) 32K. Size "can vary, even within the same model variant" ([Detecting available models](https://developer.apple.com/documentation/foundationmodels/detecting-available-apple-foundation-models)). The app hard-codes `BUDGET_CONTEXT_TOKENS = 4096` (`src/services/ai/model.ts`). The RN AI docs describe `apple.getModelInfo()` returning `contextSize` on iOS 26.4+ ([RN AI](https://www.react-native-ai.dev/docs/apple/generating)), but the installed `@react-native-ai/apple` 0.12.0, also the latest on npm (checked 2026-11-08), has no such API in its type definitions. Using it needs an unreleased version or a native spike.
- **Token budget.** Instructions, prompts, schemas, tools, and responses all count. Keep prompts to 1–3 paragraphs, use short property names, add `@Guide` sparingly, cap arrays with `maximumCount`, offer 3–5 tools at most, and split large tasks across sessions. `maximumResponseTokens` is only a safety net, because it can cut sentences off ([TN3193](https://developer.apple.com/documentation/technotes/tn3193-managing-the-on-device-foundation-model-s-context-window), [Managing the context window](https://developer.apple.com/documentation/foundationmodels/managing-the-context-window)).
- **Guided generation through Zod.** `Output.object` enforces enums, unions, regex, number bounds, and item counts. It does **not** enforce `z.email()`-style formats ([RN AI](https://www.react-native-ai.dev/docs/apple/generating)), so keep Zod validation after generation, as the app does.
- **Availability.** The states are `deviceNotEligible`, `appleIntelligenceNotEnabled`, and `modelNotReady` (a download in progress: "try again later"). On iOS 27, Apple Intelligence is on by default and can't be turned off ([Detecting available models](https://developer.apple.com/documentation/foundationmodels/detecting-available-apple-foundation-models)).
- **Latency.** Call `prepare()` at least a second before the first generation ([RN AI](https://www.react-native-ai.dev/docs/apple/generating)).
- **Safety.** Show the explanation from a `refusal` error. Handle `guardrailViolation` with a plain message. Never put untrusted input in instructions, because of prompt injection ([Improving safety](https://developer.apple.com/documentation/foundationmodels/improving-the-safety-of-generative-model-output)). ✅ Verified: triage, intake, and prep pass constant `instructions` and put emails and listings in `prompt`.
- **Private Cloud Compute.** PCC needs an entitlement and has a daily quota per user. Using it would break the "on-device only" promise, and the HIG requires disclosing server processing ([HIG Privacy](https://developer.apple.com/design/human-interface-guidelines/generative-ai#Privacy)). Opt-in at most.
- **Already available in the installed provider** ([iOS versions](https://www.react-native-ai.dev/docs/apple/ios-versions)): on-device transcription (iOS 26; live microphone needs iOS 27) ([Transcription](https://www.react-native-ai.dev/docs/apple/transcription)), speech synthesis, embeddings (iOS 17), and image prompts (iOS 27), so a screenshot of a listing could become intake input.
- **Android.** `@react-native-ai/android` wraps ML Kit GenAI (Gemini Nano) behind the same AI SDK interface ([RN AI Android](https://www.react-native-ai.dev/docs/android/getting-started)). It runs only on listed devices, only in the foreground, with a per-app quota, and not on emulators ([ML Kit GenAI](https://developers.google.com/ml-kit/genai)).

## 3. Platform capabilities and what Expo SDK 58 provides

| Capability | Apple guidance | Expo SDK 58 path | Constraints |
|---|---|---|---|
| **Local notifications** | Use **Time Sensitive** only for events "now or within an hour." Up to 4 actions, no "open app" buttons. No sensitive information. Generic text for hidden previews. In-app settings ([Notifications](https://developer.apple.com/design/human-interface-guidelines/notifications), [Managing notifications](https://developer.apple.com/design/human-interface-guidelines/managing-notifications)). | `expo-notifications`: `interruptionLevel: 'timeSensitive'`, `DATE` triggers, action categories with `textInput` ([docs](https://docs.expo.dev/versions/latest/sdk/notifications/)) | Needs the `com.apple.developer.usernotifications.time-sensitive` capability ([Expo iOS capabilities](https://docs.expo.dev/build-reference/ios-capabilities)). A job search can be confidential, so keep company names off the lock screen by default [INFERENCE]. |
| **Calendar** | Request only the access you need. On iOS 17+, the **EventKitUI editor needs no calendar permission** ([Accessing the event store](https://developer.apple.com/documentation/eventkit/accessing-the-event-store)). | `expo-calendar`: `createEventInCalendarAsync` (system dialog) and `writeOnlyAccess` config ([docs](https://docs.expo.dev/versions/latest/sdk/calendar/)) | Next Step `dueDate` is a date with no time (`IsoDate`), so interviews need a start time and time zone first. |
| **Widgets** | Simple, dynamic content. Deep-link to the right screen. Don't rely on color. Text ≥ 11 pt ([Widgets](https://developer.apple.com/design/human-interface-guidelines/widgets)). | `expo-widgets`: home and lock screen families, timelines, interactive buttons (iOS 17), Android opt-in ([docs](https://docs.expo.dev/versions/latest/sdk/widgets/)) | Isolated runtime: Expo UI SwiftUI only, no hooks, data passed in as props. |
| **Live Activities** | Only for events with a clear start and end, under 8 hours. No sensitive information ([Live Activities](https://developer.apple.com/design/human-interface-guidelines/live-activities)). | `expo-widgets` `createLiveActivity`, `start(props, url, staleDate)` | Must start in the foreground. ActivityKit can schedule with `startDate` ([ActivityKit](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities)), but the Expo API has no start date, so scheduling would need native code [INFERENCE]. |
| **App Intents / Shortcuts / Siri / Spotlight** | Offer shortcuts for the most common tasks. Each phrase includes the app name. Limit of 10. Make shortcuts discoverable in the app ([App Shortcuts](https://developer.apple.com/design/human-interface-guidelines/app-shortcuts)). | `expo-app-intents` (**alpha**): Swift declarations in inline modules, entity catalog from JS, Spotlight through `IndexedEntity`, donations, `hideInSpotlight` ([docs](https://docs.expo.dev/versions/v58.0.0/sdk/app-intents/)) | Intents must be declared in Swift at build time. On-screen entity tagging needs Xcode 27. |
| **Share extension** | — | Already configured with `expo-sharing` (URL + text). `supportsImageWithMaxCount` would add screenshots ([docs](https://docs.expo.dev/versions/v58.0.0/sdk/sharing/)). | iOS sharing is **experimental**: it opens the main app, which "may stop working in a future iOS release." |
